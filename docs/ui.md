# UI 규칙

화면은 로그인, 카탈로그(홈), 콘텐츠 상세, 플레이어, 계정, 출처 여섯 개뿐이다. 이 프로젝트의 중심은 플랫폼이라 UI에 시간을 많이 쓰지 않는다. 대신 AI가 만든 티가 나지 않게 최소한의 기준만 정한다.

## 이름

서비스 이름은 **Stillcut**이다 (2026-10-14). 헤더와 탭 제목에 글자로만 쓴다. 아이콘 로고는 만들지 않는다.

- 같은 이름의 영상 서비스가 있는지 검색으로만 확인했다. 상표 등록 여부는 확인하지 않았다.

## 방향

OTT 서비스들이 공통으로 쓰는 구조를 따른다. 영상이 주인공이고 화면은 뒤로 빠진다.

- 어두운 배경, 글자는 적게, 이미지(포스터·스틸컷) 위주
- 구조는 빌리지만 브랜드는 빌리지 않는다. 특정 서비스의 대표 색, 로고, 글꼴을 쓰지 않는다. 클론처럼 보이면 포트폴리오에서 오히려 손해다
- 강조색은 앰버(`accent`)다. 빨강(넷플릭스·티빙)과 파랑(웨이브)은 그 서비스의 색이라 피한다

참고한 구조 (2026-10-14 조사)

| 출처 | 가져온 것 |
|---|---|
| 넷플릭스 웹 | 거의 검은 바탕. 맨 위 큰 대표 작품과 그 위에 글자를 읽히게 하는 어두운 막. 장르별 가로 줄과 좌우 넘김 버튼. 호버하면 정보가 조금 늘어남. 타일 아래쪽의 짧은 상태 표시("새 시즌" 등) |
| 티빙 | 상단 고정 메뉴로 1단계 화면(홈, 계정)에 바로 들어감. 오리지널·라이브에만 붙는 배지 |
| Apple TV 웹 | 화면 폭을 다 쓰는 16:9 대표 스틸컷, 왼쪽 아래 제목·한 줄 정보·짧은 줄거리(3줄까지). 흰 재생 버튼. 줄마다 포스터형과 가로형을 섞음. 제목은 이미지 안이 아니라 아래에 |
| MUBI | 작품 수가 적어도 스틸컷을 크게 써서 빈약해 보이지 않게 함. 작품 정보에 감독·출처를 글자로 적음 |

- 세 서비스 모두 이미지 위 글자는 **검은색 반투명 그라데이션**으로 읽히게 한다. 색이 있는 그라데이션은 쓰지 않는다. 그래서 그라데이션 금지 규칙에서 이 경우만 따로 뺐다 (아래 "하지 않는 것")

## 화면 구조

| 화면 | 구조 |
|---|---|
| 카탈로그(홈) | 위에 대표 작품 하나(화면 폭 16:9 스틸컷 + 제목 + 줄거리 + 재생·상세 버튼), 아래에 가로로 넘기는 줄. "지금 볼 수 있는 작품"은 포스터(2:3), 나머지는 스틸컷(16:9). 넘김 버튼은 줄이 넘칠 때만 |
| 상세 | 홈과 같은 대표 스틸컷 위에 제목, 한 줄 정보(길이·등급), 재생 버튼, 설명. 아래에 러닝타임·이용 등급·출처. 구독 등급이 부족하면 재생 버튼 자리에 이유와 계정 화면 링크 |
| 플레이어 | 검은 바탕에 영상만. 나가기 버튼은 입력이 있을 때만 보인다. 재생 진단 패널은 개발자 모드에서만 (아래 "개발자 모드") |
| 계정 | 현재 구독 등급, 등급 변경(모의 구독이라고 표시), 로그아웃. 목록 형태 |
| 로그인 | 가운데 좁은 폼 하나. 뒤에 작품 스틸컷을 어둡게 깐다 (장식이 아니라 서비스가 무엇인지 보여주는 이미지) |
| 출처 | 작품별 제작·라이선스·원본 링크. 바닥글에서 들어간다 |

## 토큰

색과 글꼴은 `web/src/index.css`의 `@theme`에 정의한 것만 쓴다. Tailwind 기본 팔레트는 꺼 두었기 때문에 `bg-amber-50` 같은 클래스는 스타일이 생기지 않는다. 값은 첫 화면을 만들고 실제로 보면서 조정한다.

| 토큰 | 용도 |
|---|---|
| `bg` | 페이지 배경 |
| `surface`, `surface-raised` | 입력창, 메뉴, 플레이어 조작 영역 |
| `line` | 구분선, 입력창 테두리 |
| `text`, `text-muted` | 본문, 보조 정보 |
| `accent` | 키보드 포커스 테두리, 현재 메뉴 표시 정도. 버튼 바탕에는 쓰지 않는다. PREMIUM 같은 라벨에도 쓰지 않는다 |
| `danger` | 오류 문구 |
| `scrim` | 플레이어 위 패널·안내처럼 영상 위에 올리는 어두운 면 |
| `black` | 플레이어 바탕 |

- 주요 버튼(재생, 로그인)은 흰 바탕(`bg-text`)에 검은 글자. 보조 버튼은 반투명 흰 바탕(`bg-text/20`)
- 이미지 위 그라데이션은 `index.css`의 `scrim-hero`(대표 스틸컷), `scrim-top`(헤더·플레이어 위쪽), `scrim-card` 세 유틸리티만 쓴다. 모두 검은색 투명도만 바꾼다

- 글꼴은 Pretendard. 없으면 시스템 한글 글꼴
- 포스터 비율은 2:3, 스틸컷은 16:9로 고정한다. 이미지가 늦게 와도 레이아웃이 밀리지 않는다
- 모서리는 작게(`rounded-sm`~`rounded-lg`). 포스터에 그림자·테두리를 붙이지 않는다. 이미지가 곧 카드다

## 하지 않는 것

AI가 만든 화면에 자주 나오는 장식이다. 맥락 없이 어디에나 같은 장식을 붙이기 때문에 티가 난다.

| 패턴 | 강제 |
|---|---|
| 카드 왼쪽 색 띠 (`border-l-*`) | ESLint |
| 그라데이션 배경, 그라데이션 글자. 이미지 위 검은 막(`scrim-*`)만 예외 | ESLint (`className`의 `bg-linear-*` 등) |
| 유리 효과 (`backdrop-blur`) | ESLint |
| 큰 둥근 모서리(`rounded-2xl` 이상), 큰 그림자(`shadow-lg` 이상) | ESLint |
| 임의 색 값 (`bg-[#...]`) | ESLint |
| 화면 문구 속 이모지 (©®™는 허용) | ESLint |
| 깜빡이는 배지 (`animate-pulse`, `animate-ping`, `animate-bounce`) | ESLint |
| 크림·베이지 배경 | 기본 팔레트를 꺼서 쓸 수 없음 |
| 흰 카드 + 둥근 모서리 + 그림자 + 테두리를 한꺼번에 | 리뷰 |
| 같은 크기 카드 세 개를 나란히 둔 소개 섹션 | 리뷰 |
| 색 동그라미 안 아이콘 | 리뷰 |
| 모든 요소 가운데 정렬 | 리뷰 |
| 카드 안에 카드를 겹쳐 넣기. 묶음은 여백과 글자 크기로 나눈다 | 리뷰 |
| 아무 상태도 뜻하지 않는 색 점. 점을 쓰면 글자 라벨과 실제 상태가 같이 있어야 한다 | 리뷰 |
| 배경의 오로라·빛 번짐 효과, 빛나는 글자 | 리뷰 |
| 모든 화면을 랜딩 페이지처럼 만들기. 홈 말고는 기능 화면이다 | 리뷰 |

장식 클래스 검사는 `web/eslint/ui-rules.js`가 한다. `className`에 문자열로 쓴 클래스만 본다.

이 목록의 근거는 AI가 만든 화면의 특징을 정리한 글들이다 ([Fountain Institute, 7 Signs a UI Has Been Vibe Coded](https://www.thefountaininstitute.com/blog/signs-vibe-coded-ui) 등). 대부분 의견 글이라, 규칙으로 정한 것은 여러 글에서 겹치는 항목만이다.

## 이미지

포스터(2:3, 600×900)와 스틸컷(16:9, 1600×900)은 앱 정적 파일 `web/public/artwork/{id}/poster.jpg`, `still.jpg`에서 읽는다. `/content/*`는 Signed Cookie가 필요해서 카탈로그 이미지를 둘 수 없다. 이미지가 없으면 같은 비율의 빈 면만 둔다 (제목은 아래 글자로 이미 있다).

- 작품은 Blender Studio 오픈 무비 네 편이다. 라이선스(CC BY 4.0, Elephants Dream은 CC BY 2.5)에 따라 출처 화면(`/credits`)과 상세 화면에 제작·라이선스·원본 링크와 바꾼 내용을 적는다. 목록은 `web/src/features/credits/credits.ts`
- 공식 포스터가 있는 작품(Spring, Coffee Run)은 그것을 2:3으로 자르고, 없는 작품(Wing It!, Elephants Dream)은 영상 프레임을 잘라 만들었다. 스틸컷은 모두 영상 프레임이다

## 문구

- 짧게, 존댓말 평서문. "PREMIUM 구독이 필요합니다"처럼 무엇이 문제인지만 쓴다
- 느낌표, "~해보세요!", "환영합니다"류 인사, 기능을 자랑하는 문장을 쓰지 않는다
- 오류 문구는 API의 `code`로 고른다. 같은 `code`면 어느 화면에서나 같은 문구다

## 상태

- 로딩: 포스터·스틸컷 비율 그대로의 빈 자리. 스피너는 플레이어 버퍼링에만
- 빈 목록: 한 줄 문구. 일러스트를 넣지 않는다
- 오류: 4xx는 그 자리에 문구, 5xx는 Error Boundary (FE-07)

## 개발자 모드

재생 진단 패널은 일반 사용자에게 보이지 않는다. `?devtools=1`로 켜면 브라우저(`localStorage`의 `stillcut.devtools`)에 남고, `?devtools=0`으로 끈다. 켜진 상태의 플레이어에서 `Shift + D`로 패널을 열고 닫는다.

- 패널에는 플레이어가 실제로 잰 값만 보인다: 해상도, 렌디션, 대역폭 추정, 버퍼, 끊긴 프레임, 시작 시간, 재버퍼링, 화질 전환, 버전 경로. 대역폭 추정은 첫 세그먼트가 버퍼에 붙기 전에는 hls.js 설정 기본값이라 `-`로 둔다
- CDN POP과 캐시 결과는 세그먼트 응답의 `x-amz-cf-pop`, `x-cache` 헤더를 읽는다. 세그먼트를 받기 전은 `-`, 받았는데 헤더가 없으면(로컬 content-server) "연동 필요"로 표시한다. 앱과 영상이 같은 도메인이라 CORS 노출 설정 없이 읽힌다 (design.md 도메인 구성)
- 세션 ID는 앞 8자만 보인다. 전체 값은 남의 세션으로 QoE를 보내는 데 쓸 수 있다. 쿠키 값, 서명, 정책은 표시하지 않는다
- 화면에만 숨기는 것이므로 보안 경계가 아니다. 패널이 보여주는 값은 모두 그 사용자 브라우저가 이미 가진 것이다

## 지역 제한 안내

재생 권한 판단은 프론트가 하지 않는다. Edge가 403과 함께 `X-Playback-Denied` 헤더로 사유(`GEO_BLOCKED`, `NOT_AVAILABLE`, `POLICY_UNAVAILABLE`)를 주면 플레이어가 그 사유로 문구와 사유 코드를 보여준다 (design.md §7). 사유 헤더 없는 403이나 목록에 없는 사유는 쿠키 문제 등으로 보고 일반 오류 문구를 보인다. 거부되면 쿠키 갱신도 멈춘다. Safari 네이티브 HLS는 응답 헤더를 읽을 수 없어 일반 오류로만 알린다. 카탈로그에서 미리 숨기는 기능은 없다 (design.md §3, 1차 범위 밖).

## 확인 방법

규칙으로 잡히지 않는 부분은 결국 눈으로 본다. web 단계부터 화면을 바꾸는 PR에는 Playwright로 찍은 스크린샷을 붙인다.
