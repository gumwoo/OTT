# UI 규칙

화면은 로그인, 카탈로그(홈), 콘텐츠 상세, 플레이어, 계정 다섯 개뿐이다. 이 프로젝트의 중심은 플랫폼이라 UI에 시간을 많이 쓰지 않는다. 대신 AI가 만든 티가 나지 않게 최소한의 기준만 정한다.

## 방향

OTT 서비스들이 공통으로 쓰는 구조를 따른다. 영상이 주인공이고 화면은 뒤로 빠진다.

- 어두운 배경, 글자는 적게, 이미지(포스터·스틸컷) 위주
- 구조는 빌리지만 브랜드는 빌리지 않는다. 특정 서비스의 대표 색, 로고, 글꼴을 쓰지 않는다. 클론처럼 보이면 포트폴리오에서 오히려 손해다

## 화면 구조

| 화면 | 구조 |
|---|---|
| 카탈로그(홈) | 위에 대표 작품 하나(큰 스틸컷 + 제목 + 재생 버튼), 아래에 포스터를 가로로 넘기는 줄 몇 개 |
| 상세 | 스틸컷 배경 위에 제목, 한 줄 정보(연도·길이·등급), 재생 버튼, 설명. 구독 등급이 부족하면 재생 버튼 자리에 이유와 계정 화면 링크 |
| 플레이어 | 영상만. 조작 UI는 마우스를 움직일 때만 보인다 |
| 계정 | 현재 구독 등급, 등급 변경(모의 구독이라고 표시), 로그아웃. 목록 형태 |
| 로그인 | 가운데 좁은 폼 하나. 배경 장식 없음 |

## 토큰

색과 글꼴은 `web/src/index.css`의 `@theme`에 정의한 것만 쓴다. Tailwind 기본 팔레트는 꺼 두었기 때문에 `bg-amber-50` 같은 클래스는 스타일이 생기지 않는다. 값은 첫 화면을 만들고 실제로 보면서 조정한다.

| 토큰 | 용도 |
|---|---|
| `bg` | 페이지 배경 |
| `surface`, `surface-raised` | 입력창, 메뉴, 플레이어 조작 영역 |
| `line` | 구분선, 입력창 테두리 |
| `text`, `text-muted` | 본문, 보조 정보 |
| `accent` | 재생 버튼, 선택된 항목, 포커스. 한 화면에 한두 군데만 |
| `danger` | 오류 문구 |
| `scrim` | 스틸컷 위 글자를 읽히게 하는 어두운 막 |

- 글꼴은 Pretendard. 없으면 시스템 한글 글꼴
- 포스터 비율은 2:3, 스틸컷은 16:9로 고정한다. 이미지가 늦게 와도 레이아웃이 밀리지 않는다
- 모서리는 작게(`rounded-sm`~`rounded-md`). 포스터에 그림자·테두리를 붙이지 않는다. 이미지가 곧 카드다

## 하지 않는 것

AI가 만든 화면에 자주 나오는 장식이다. 맥락 없이 어디에나 같은 장식을 붙이기 때문에 티가 난다.

| 패턴 | 강제 |
|---|---|
| 카드 왼쪽 색 띠 (`border-l-*`) | ESLint |
| 그라데이션 배경, 그라데이션 글자 | ESLint |
| 유리 효과 (`backdrop-blur`) | ESLint |
| 큰 둥근 모서리(`rounded-2xl` 이상), 큰 그림자(`shadow-lg` 이상) | ESLint |
| 임의 색 값 (`bg-[#...]`) | ESLint |
| 화면 문구 속 이모지 | ESLint |
| 크림·베이지 배경 | 기본 팔레트를 꺼서 쓸 수 없음 |
| 흰 카드 + 둥근 모서리 + 그림자 + 테두리를 한꺼번에 | 리뷰 |
| 같은 크기 카드 세 개를 나란히 둔 소개 섹션 | 리뷰 |
| 색 동그라미 안 아이콘 | 리뷰 |
| 모든 요소 가운데 정렬 | 리뷰 |

장식 클래스 검사는 `web/eslint/ui-rules.js`가 한다. `className`에 문자열로 쓴 클래스만 본다.

## 문구

- 짧게, 존댓말 평서문. "PREMIUM 구독이 필요합니다"처럼 무엇이 문제인지만 쓴다
- 느낌표, "~해보세요!", "환영합니다"류 인사, 기능을 자랑하는 문장을 쓰지 않는다
- 오류 문구는 API의 `code`로 고른다. 같은 `code`면 어느 화면에서나 같은 문구다

## 상태

- 로딩: 포스터·스틸컷 비율 그대로의 빈 자리. 스피너는 플레이어 버퍼링에만
- 빈 목록: 한 줄 문구. 일러스트를 넣지 않는다
- 오류: 4xx는 그 자리에 문구, 5xx는 Error Boundary (FE-07)

## 확인 방법

규칙으로 잡히지 않는 부분은 결국 눈으로 본다. web 단계부터 화면을 바꾸는 PR에는 Playwright로 찍은 스크린샷을 붙인다.
