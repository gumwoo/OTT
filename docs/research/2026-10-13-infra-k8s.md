# Terraform·Kubernetes·Helm·Argo CD 컨벤션 조사 (2026-10-13)

## 0. 요약

- **Terraform 원격 상태**: S3 backend `use_lockfile`은 1.10에서 experimental, **1.11.0(2025-02-27)에서 GA**. 같은 릴리스에서 DynamoDB 인자 deprecated. `required_version >= 1.9`로는 보장 못 함 → **`>= 1.11`**.
- **Argo CD 추적**: v3.0부터 기본 **annotation**(`argocd.argoproj.io/tracking-id`). CLI로 만든 Job에 `app.kubernetes.io/instance` 라벨이 있어도 annotation이 없으면 앱 리소스로 보지 않는다. `argocd-cm`에 명시 고정 권장.
- **우리 구조의 위험** (추론): ad-hoc Job Pod가 API Service selector 라벨과 겹치면 TargetGroupBinding을 통해 ALB 트래픽이 들어갈 수 있다.
- **GitHub Actions**: GitHub 공식은 SHA pinning 권장. terraform-aws-modules는 태그 고정. 공식 권고를 따른다.

## 4. Argo CD 추적 방식과 ad-hoc Job

- 확인: 기본 annotation(`argocd.argoproj.io/tracking-id`), 3.0에서 label → annotation. label 방식은 Helm이 붙인 같은 라벨 때문에 소유자를 혼동할 수 있다고 문서가 경고. Orphaned Resources는 경고·표시용. auto-sync 앱은 rollback 불가.
- 결론: annotation 방식이면 CLI Job에 instance 라벨이 있어도 tracking-id가 없는 한 prune 대상이 아니다 (확신도 중간~높음, 직접 다룬 문장은 없음).
- 권장: (1) `argocd-cm`에 `application.resourceTrackingMethod: annotation` 명시 (2) CLI Job은 Helm 렌더링 결과를 복사하지 않고 `managed-by`·`component`로 구분 (3) orphanedResources를 켜면 `batch/Job` + `transcode-*` ignore (4) 롤백은 Git revert만.

## 5. 우리 설계와 충돌·주의점

1. `required_version >= 1.9`와 `use_lockfile` 충돌 → `>= 1.11`.
2. Service selector 충돌 (추론): Service·PDB·topologySpread selector에 `component: api` 포함.
3. LBC는 Terraform이 만든 TG를 완전히 제어. 다른 용도와 공유 금지. compute destroy 전에 Argo 앱(TGB)을 먼저 삭제.
4. VPC origin(compute)과 distribution(base)의 의존 방향: SSM 경유 단방향 설계 필요 (문서 근거 없는 설계 의견).
5. 로컬 state로 compute를 추가하지 말 것. S3 backend 이전과 SSM 값 전달을 먼저.
6. `backoffLimit: 0`과 노드 drain: drain 한 번에 Job 실패. podFailurePolicy로 Ignore할지, 실패로 둘지 결정.
7. `ttlSecondsAfterFinished`로 Job이 사라지면 로그·상태도 사라진다. 결과는 DB·S3에 먼저 기록.
8. terraform-aws-modules를 action 고정 방식의 근거로 쓰지 않는다.
9. IMDS hop limit 1이면 LBC 등에 플래그로 값을 넘겨야 할 수 있다 (미확인).

## 6. 확인하지 못한 것

- Terraform·Argo CD·tflint 최신 릴리스 번호 (GitHub API 403)
- `podFailurePolicy`의 `restartPolicy: Never` 제약 원문, ephemeral-storage eviction이 `DisruptionTarget`인지
- emptyDir `sizeLimit` 공식 원문
- EKS Pod Identity와 `automountServiceAccountToken: false` 호환성
- LBC의 IMDS hop 1 플래그, TargetGroupBinding finalizer와 삭제 동작
- CloudFront VPC origin stack 분할 공식 가이드
- Argo CD annotation 방식에서 "라벨만 있는 리소스" 처리 문장
- GitHub Actions "lockfile" 기능 세부
- checkov·terraform-docs 공식 문서
