# 프론트엔드 컨벤션 조사 (2026-10-13)

범위: React, TypeScript, Vite, React Router, TanStack Query, Tailwind CSS, hls.js, Vitest, Playwright, ESLint/Prettier.

## 0. 요약

- **React Router는 v8.4.0.** 정적 SPA에는 Data mode(`createBrowserRouter` + `react-router/dom`의 `RouterProvider`). v8에서 `react-router-dom` 패키지 제거, middleware 상시 활성.
- **버전 고정 필요**
  - TypeScript: npm latest 7.0.2지만 typescript-eslint 지원 범위가 `>=4.8.4 <6.1.0`. **6.0.x 고정**. Vite 템플릿도 `~6.0.2`.
  - eslint-plugin-jsx-a11y: 최신 6.10.2(2024-10)의 peer가 ESLint `^9`까지, v10 지원 이슈(#1075) open. **ESLint 9 유지**.
  - MSW 3.0: 2026-09-28 출시. 도입 전 마이그레이션 문서 확인.
- **도구 동향**: Vite react-ts 템플릿과 Kent C. Dodds의 `@epic-web/config`는 oxlint(+oxfmt)로 이동.
- **설계 충돌**: QoE에 `sendBeacon`을 쓰면 CSRF 헤더를 붙일 수 없다. CloudFront 커스텀 에러 응답으로 SPA fallback을 만들면 `/api/*` 403/404도 덮일 수 있다. Playwright 번들 Chromium에는 일부 코덱이 없다.

## 4. 추천 구성 요약

- **tsconfig.app.json**: Vite 템플릿 + `strict`, `noUncheckedIndexedAccess`. `exactOptionalPropertyTypes`·`baseUrl` 미사용. typescript `~6.0.x`.
- **eslint.config.js (ESLint 9)**: `@eslint/js` recommended → `tseslint.configs.recommendedTypeChecked`(projectService) → react-hooks → `@tanstack/query` `flat/recommended-strict` → jsx-a11y → 사용자 규칙(no-floating-promises, no-misused-promises, consistent-type-imports, `no-restricted-globals: fetch`, `no-restricted-imports: react-router-dom`) → 테스트 파일 override(testing-library, jest-dom) → `*.js`에 `disableTypeChecked` → `eslint-config-prettier`.
- **.prettierrc**: `plugins: ["prettier-plugin-tailwindcss"]`, `tailwindStylesheet`.
- **CI**: `tsc -b` → `eslint .` → `prettier --check .` → `vitest run` → `vite build` → `playwright test`.

## 5. 우리 설계와 충돌·주의점

1. QoE와 CSRF: `sendBeacon`은 헤더를 붙일 수 없다. `fetch keepalive`(64KiB 제한) 또는 `/api/qoe`만 CSRF 예외(트레이드오프 문서화).
2. CloudFront 커스텀 에러 응답은 distribution 단위라 `/api/*` 응답도 덮일 위험 (설정 위치에서 추론).
3. `PLAN_REQUIRED`와 CSRF 실패가 둘 다 403. 서버가 `code: CSRF_INVALID`를 내려줘야 클라이언트가 구분할 수 있다.
4. 로그인·로그아웃 직후 `GET /api/csrf`, `/api/csrf`는 permitAll.
5. 버전 고정: TS 6.0.x, ESLint 9. React Router v8은 React 19.2.7+·Vite 7+.
6. TQ의 react-router 예제와 TkDodo 2022년 글은 RR v6 기준.
7. RR "SPA mode" 문서는 Framework mode 전용. Data mode SPA 구성은 직접 설계.
8. hls.js ESM은 `workerPath`가 없으면 메인 스레드에서 transmux (성능 영향 미측정).
9. StrictMode 개발 모드에서 QoE 세션·타이머가 두 번 생길 수 있다.
10. Playwright 번들 Chromium 코덱 제한.
11. Vite 공식 템플릿은 oxlint 기본. ESLint로 가면 직접 구성.
